# StudyGame 文档说明

> 当前执行入口：根目录 `todo.md`  
> 本目录用途：保留基础资料、内容设计参考和历史研究，不直接作为当前排期依据。

## 使用原则

- 多 agent 协作规则以根目录 `AGENTS.md` 为准。
- 当前 RPG 主体验重构的范围、优先级、验收标准，以根目录 `todo.md` 为准。
- `docs/` 中的资料用于查证内容来源、补充世界观、参考长期方向。
- 根目录 `lessons.md` 用于记录已踩坑点和质量红线，各组开工前应阅读。
- 如果 `docs/` 中的旧方案与 `todo.md` 冲突，以 `todo.md` 为准。
- 不从历史文档中直接追加功能到 P0，必须先回到 `todo.md` 更新范围和验收标准。

## 文档分类

### 当前协作规则与质量红线

- 根目录 `AGENTS.md`
- 根目录 `todo.md`
- 根目录 `lessons.md`

用途：

- `AGENTS.md` 定义多 agent 协作规则、角色边界和交付标准。
- `todo.md` 定义当前 RPG 主体验重构 P0 的产品范围、路线图和验收标准。
- `lessons.md` 记录已经犯过的错、踩过的坑和后续各组必须避开的质量红线。

维护原则：

- PM 负责更新 `todo.md` 和 `lessons.md`。
- 任何新坑复现后，应先记录到 `lessons.md`，若形成阻断项再同步到 `docs/P0开发看板.md`。
- `lessons.md` 不直接扩大 P0 范围，范围变化仍必须先更新 `todo.md`。

### 当前执行与验收

- `P0开发看板.md`
- `P0阶段验收报告.md`

用途：

- `P0开发看板.md` 跟踪当前 RPG 主体验重构 P0 的派工、阻断项和验收项。
- `P0阶段验收报告.md` 记录上一轮 RPG-lite P0 已经验证的证据、未关闭项和 PM 结论。

维护原则：

- P0 执行过程中优先更新 `P0开发看板.md`。
- 每次阶段性验收后更新 `P0阶段验收报告.md`。
- 如果范围或优先级变化，先回到根目录 `todo.md` 调整。

### 历史阶段资料

- `RPG-lite P0开发任务书.md`

用途：

- 记录上一轮 3 任务 RPG-lite 垂直切片的目标、分工和验收口径。
- 可用于追溯成长、奖励、冒险日志和 P0 三任务闭环的来源。

注意：

- 当前项目已进入 RPG 主体验重构阶段。
- 若本文档与 `todo.md` 冲突，以 `todo.md` 为准。

### 基础资料

- `小学英语重点分析/`

用途：

- 作为小学英语词汇、句型、语法和原文语料来源。
- 支撑后续任务、知识点、奖励和家长摘要的内容追溯。
- 可用于内容扩展，但不直接决定产品功能范围。

维护原则：

- 可以补充或修订语料。
- 修改后需要同步检查内容配置和任务引用。

### 内容设计参考

- `小学英语故事线与关卡内容设计.md`

用途：

- 作为星光小镇、故事钟塔、七段星路、星片奖励等世界观参考。
- 支撑 RPG-lite 冒险主线、章节目标和任务包装。
- 后续第一章扩展到 10 个任务时，应优先参考此文档。

维护原则：

- 可以作为剧情和关卡设计依据。
- 具体开发范围仍需写入 `todo.md` 后再执行。

### 背景研究

- `面向7–12岁小学生的芭比主题养成类 AI 游戏完整开发方案.md`

用途：

- 作为儿童产品、教育游戏、合规、安全和长期商业化方向的背景研究。
- 可帮助理解为什么要做隐性学习、场景化学习和家长可解释报告。

注意：

- 当前项目采用原创 RPG-lite 方向，不直接使用 Barbie IP。
- 本文档不能作为当前版本的功能清单。

### 历史 / 长期技术研究

- `项目策划及开发方案生成.md`

用途：

- 作为长期技术架构、AI 内容生成、多代理、后端和数据系统的研究材料。
- 可在未来进入联网、多端、AI 生成内容或服务端架构阶段时参考。

注意：

- 当前技术基线仍是 Vite + React + Phaser 3 + 本地存储。
- 本文档中的 Next.js、RAG、多代理、数据库、服务端方案不进入当前 P0。

## 当前不建议恢复的文档类型

- 旧 MVP 验收记录。
- 临时截图报告。
- 素材生成中间记录。
- 已废弃路线图。
- 与当前 RPG-lite 计划冲突的旧任务清单。

如果确实需要恢复，应先说明用途，并在本 README 中补充分类。
