# 字母岛二级地图、校园与家庭三级场景制作策划

版本：v04。视觉与主词基准：Blender v05；运行主图：v05 派生的 v06_game。家庭层级本轮已接入 Godot，来源和运行证据见 [家庭场景说明](planning/home-hierarchy/README.md)。本文件仍包含其他地图的制作方向，不表示全部生活委托或学习任务已经实现。

本次覆盖 A—Z 26 个字母地标、完整校园与玩家住宅，共 **28 个二级场所**。学校采用“一级主岛 `village` → 二级完整校园 `school` → 七个三级场景”；家庭采用“一级主岛 → 二级小院 `home_estate` → 室内门厅 `home_hall` → 七个三级房间”。门厅是住宅的室内通行状态，不新增学习层级。28个二级场所、14个三级房间和1个门厅导航空间合计独立导出 **43 个场景**，不计一级主岛；42个活动场景各有五个固定记忆位置，仍为 **210 个场景绑定**，门厅不新增知识点。

机器清单：[landmark_interiors.json](../game/data/landmark_interiors.json)。主词和地标名称逐项沿用[世界设计](字母地标与记忆宫殿世界设计.md)与 v05 放置清单。活动和英语例句是后续设计方向，可用于地点介绍与自由探索卡，不代表正式测评、已实现生产流程或完整教材覆盖。

## 2. 建模与入口绑定

- 各 GLB 保留 `SG_SPAWN`、`SG_EXIT`、`SG_MEMORY_01` 至 `SG_MEMORY_05`、`SG_NPC_HOST`。记忆节点对应清单中的稳定 `memory_*` ID。每图局部节点允许同名，运行时通过 `room_id` 区分。
- 二级 `school` 增加七门：`SG_DOOR_CLASSROOM`、`SG_DOOR_MUSIC_ROOM`、`SG_DOOR_ART_ROOM`、`SG_DOOR_SCIENCE_ROOM`、`SG_DOOR_CANTEEN`、`SG_DOOR_PLAYGROUND`、`SG_DOOR_FOOTBALL_FIELD`。七个三级场景的 `SG_EXIT` 均回到校园对应门前；只有校园自己的 `SG_EXIT` 返回一级主岛学校校门外。
- `school.scene_level=2`、`parent_room=village`；七个 `school.areas` 均为 `scene_level=3`、`parent_room=school`、`separate_scene=true`。稳定入口交互统一为 `<room_id>_gate`；`model_bindings.doors` 与子场景 `return_to.door_node`、`return_to.interaction_id` 必须一一对应，不能根据数组序号猜回程门。
- 旧 `home` 保留为三级客厅，保留原五点、衣柜与三个独立装饰物件；休息功能使用 `home_bedroom` 的 `SG_BED`。旧客厅源文件另存为 `home_v01`，新客厅为 `home_v02`。
- 二级 `home_estate` 使用唯一正门 `SG_HOUSE_ENTRY`，运行交互名为 `house_entry`；进入后加载住宅的室内门厅 `home_hall`，角色继续在屋内行走。门厅有七个 `SG_DOOR_*` 实体房门，分别绑定 `<room_id>_gate`。每个三级房间的 `home_exit` 回门厅对应房门；门厅 `courtyard_exit` 返回小院正门，院落 `village_exit` 再回主岛。
- A—Z、二级校园与二级住宅经 `SG_EXIT` 返回同一主地图地标入口前。v06_game 为28主目的地提供 `SG_DOOR_A` 至 `SG_DOOR_Z`、`SG_DOOR_HOME`、`SG_DOOR_SCHOOL`；返回绑定这些实体门标记并确认门外可行走站位。主图程序房间名沿用 `village`；`world_socket`/外观参考对象只用于辨认地标，不能把建筑中心直接作为人物落点。
- Blender 单位米、Z 向上、默认前门朝本地 -Y。引擎读取实际导入变换。以从入口看向内部定义左/中/右，固定默认镜头方向。
- 出生点在门内可站立区，与出口触发区分开，避免入场立即返回。回程落点也需站在主地图门外通路上。
- 前墙、屋顶、高遮挡物独立分组或切除。默认倾斜俯视镜头能看见角色、五点操作面和出口。
- 先按约 1.8–2.4 米主通道、操作点前约 1.5 米回转空间做尺度样板；这是制作建议，后续用真实角色核验。A 已有点位优先保留，道路配合旧点。

运行主图文件：[v06_game GLB](../assets/blender/alphabet_island/alphabet_island_layout_v06_game.glb)，入口清单：[game_map_manifest.json](../assets/blender/alphabet_island/game_map_manifest.json)。v06只为运行接入增加标记等必要适配，不重排旧130记忆锚点。

## 3. 源资产继承

### A 果园

复用 [A_orchard v02](../assets/blender/A_orchard/README.md)。保留门前篮子→左侧果树→分拣台→洗果池→礼物架的不规则实际布局，不为“入口/左/中/右/出口”的抽象顺序重新搬位。JSON保留 `A_LOCUS_01...05` 原名与坐标，`SG_MEMORY_01...05` 是兼容别名。苹果屋外壳尚无室内与可通行门洞；本轮以果园主题空间作为二级地图，未来屋内另立命名空间。

### 学校

校园复用 [school v01](../assets/blender/school/README.md) 中的钟楼教学楼、真实球场及其他可用外观，材质参考整岛 v05；在保留源文件的前提下派生完整校园版本。足球场扩展另存为 `school_v03`，保留原建筑与旧SG节点坐标，向东增加足球场和连接步道。旧五点“校门→教室前→图书角→操场→食堂窗口”属于 `school_anchor_sequence`，保留其源节点；新校园及七个三级场景各有自己的五点，不用旧节点占位坐标替代实际新位置。完整校园需要看得见的教学楼、音乐楼、美术楼、科学楼、餐厅、操场、足球场、庭院、道路和绿化。

**v05 的五个 `ALPHA_SCHOOL_ANCHOR_*` 坐标均为 `(0,0,0)` 占位，只能参考名称。** 主地图接入层的 `SG_DOOR_SCHOOL` 由两座实际校门石柱 bounds 中点推导，再确认可行走落点。新的二级学校 `SG_*` 必须在对应场景实际放置，不能复制零坐标。

### 家园与其他地标

HOME 是玩家住宅，不占 M；M 是固定的蘑菇邻居客厅。学校不占 S，S 继续为 Star 天文台。旧客厅五点坐标与内部标识保留，中央桌改按茶几组织内容，窗边阅读角加入家人相册；床移入独立卧室。奖励家具放额外装修位。主地图地标和旧 130 点不移动；旧源模型与工程不覆盖。

### HOME · 完整住宅与七个房间（Home）

二级场景：`home_estate`，`parent_room=village`。小院有信箱、花圃、随身篮、日程板和门廊树五点；住宅呈现完整封闭外观。正门进入可行走的 `home_hall` 室内状态。玄关、中央通道和横向走廊连接七扇带用途标识的实体门，人物可直接步行，也可用室内地图导航到门前。

| 三级房间 | 房间标识 | 主要生活内容 |
|---|---|---|
| 家里的客厅 | `home` | 招待朋友、介绍家人、装扮与共同回忆 |
| 温暖卧室 | `home_bedroom` | 整理床铺、作息、穿搭、书包与睡前阅读 |
| 明亮厨房 | `home_kitchen` | 食物储存、洗菜、做饭、备餐与清洁 |
| 家庭餐厅 | `home_dining` | 早餐、水果喜好、摆餐具、生日与节日团聚 |
| 清爽浴室 | `home_bathroom` | 刷牙、洗手、洗脸、保持清洁与关水 |

四上 Unit 9 是客厅、卧室、厨房、浴室等房间知识的直接依据；餐厅、书房和家务阳台是结合其他册吃饭、阅读、电脑与家务内容划出的功能空间。40句教材原文与缓存语音逐条关联到物件，册次、单元、页码和区域记录见 [来源审计](planning/home-hierarchy/source-audit.json)。住宅建筑和八个三步生活流程是原创设计；生活体验单独保存，不增加教材通关或语言掌握记录。

完整五点清单、活动和来源边界见 [家庭场景说明](planning/home-hierarchy/README.md)；游戏内画面见 [场景预览](home-hierarchy-gallery.html)。

## 5. 制作顺序与验收

优先完成 HOME、完整校园 school 与 classroom/music_room/art_room/science_room/canteen/playground/football_field 七个三级场景、A、C 的角色尺度、镜头、入口和导出样板，再做 B/F/H/M/O/Z，最后扩展其他地图。它只是资产制作优先级，不是教材顺序，也不表示未答对不能参观地标。

| 检查项 | 通过条件 | 证据边界 |
|---|---|---|
| 完整性 | 28二级场所＋14三级＋1室内导航，共43场景ID、210固定点；42活动场景公共8节点，门厅出生/出口/七门节点齐全 | 有节点不等于游戏逻辑完成 |
| 命名一致 | I=Ice cream、Q=Quilt、X=Xylophone、Y=Yarn，学校/Home独立，五点ID稳定 | 地标字母关系不代替自然拼读 |
| 差异化 | 隐去名称仍可区分A/F/P、C/I、D/X、H/Q/Y、B/T、G/S/U/V、O/Q、M/Home | 平面、中心装置和活动流程都应有区别 |
| 可行走 | 真实角色走完入口→五点→出口，操作面可见可达，无卡住或传送回环 | 渲染图不能代替引擎行走验收 |
| 往返绑定 | 主岛进入完整校园；真实步行七门、七个三级场景各五点和出口；各自回校园正确门，最后校园回主岛。家居三装饰分别显示 | 不以直接调用传送代替人物走到门前与最近交互验收 |
| 语言自然 | 活动有生活目的，未知词先教，提示/独立理解/词块辅助/跟读分开 | 新编例句不虚构教材来源或学习效果 |
| 交付证据 | 每图blend、GLB、默认镜头预览、节点/面数/贴图清单及来源说明齐全 | 静态素材、导入、交互验收分别标记 |

学校专项还需验证校园地图的九个导航入口（七处三级场景、主岛出口、校园五点页）及五点页回到校园地图；关闭按钮不计入九个导航入口。

建模会话负责资产与静态检查；主会话负责主图接入、碰撞、寻路、传送和具体玩法。完成某图后在独立资产清单登记，不直接把本策划状态批量改成“全部完成”。

## 6. JSON 使用边界

`landmarks` 顶层有28项，对应28个二级场景；SCHOOL和HOME各自的七个三级场景列在 `areas` 中，标记 `separate_scene=true`、`scene_level=3` 和对应 `parent_room`。顶层140锚点加14个三级场景70锚点，共210。`first_activity`、`anchors.label/activity`均为文字，`english_focus`为文字数组，可用于地点介绍。家庭具体内容还由 `home_hierarchy.json` 提供。原有课程仍由 `curriculum.json` 管理；发现点、家务体验与语言学习进度分别保存。
