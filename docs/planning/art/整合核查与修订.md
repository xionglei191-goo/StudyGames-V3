# 主线、词汇与美术整合核查与修订

日期：2026-10-22。状态：策划整合与静态核查；全部新增模型、动画、动态天气和记忆舞台仍未实施。总入口见[总游戏设计文档](../../../GDD.md)。

## 1. 核查范围与结论边界

本轮逐项比对[主线目录](../mainline/README.md)、[词汇目录](../vocabulary/README.md)和本目录资产规格。核查对象包括26字母序章、八册教材章节、词汇真实token/分镜/存放索引、教材人物来源和活动、环境/演出时钟，以及模型制作与替换流程。修改集中在美术策划和本目录的结构化接口，没有改动教材文本、词义或故事内容，也没有改动游戏脚本、地图、模型、碰撞、SG锚点或构建产物。

完整性核验结果见[validation_report.json](validation_report.json)。其中PASS只表示检查过的身份、引用、拼写顺序、来源指纹和规划契约相符。它不表示142条教材身份的模型已经完成，也不表示40项动作已生产、天气已接入、学习效果已验证。

## 2. 已修订的实质问题

| 原来的缺口或歧义 | 本轮修订 | 验证方式 |
|---|---|---|
| 文案要求26个故事形象，但没有可以交接的资源表 | 新增[mnemonic_story_assets.json](mnemonic_story_assets.json)，列26缩景、8类符号、10舞台组件和20个真实词例 | 逐字母与序章及词汇codebook对照，既有源文件必须存在 |
| 图片代表物与英语词义可能混为一谈，尤其E的“蛋壳” | 保留Egg/鸡蛋的词义和E映射；代表物明确为完整蛋形，可开合、可复位，碎壳不能独立代表Egg词义 | 与词汇统一codebook及序章的双标签契约比较 |
| 重复字母、空格与标点缺少实例和位置契约 | 定义级字母用`story_id + letter_position`；非字母用`story_id + surface_position`，运行实例再加本次`invocation_id`且恢复保留，完整保留raw跨度 | `book`两个O不得合并；`from... to...`的三个点是一段占位；原样拼回整词 |
| 支持等级描述分散，可能把H0按钮当作无提示证据 | 对齐H0–H5；H0不展示故事答案；H3的缺失答案仅评估器可见，揭示后记录所见提示 | 与词汇支持层级比对；文案与渲染契约明确隐藏要求，实装后还需UI验收 |
| 故事“镜子旁”等位置易被误当作已经存在的地图节点 | 保存词汇的固定主册/相邻义项页索引；保留`existing_scene_binding=null`和故事册承载方式 | 比较`storage`、`memory_home`原数据；不凭地点文字新增SG节点 |
| 最长词例只靠短词样板难以发现排版和恢复问题 | 纳入`International Children's Day`的25字母、7分镜与完整符号 | 连续顺序、分镜覆盖和暂停恢复规格；遵守认读及可选记忆权限，不强制拼写 |
| 全岛装饰动态暂停与教学中的雨/云演出边界不清 | 装饰遵守世界时钟，词义所需雨/云/晨景使用独立故事舞台和演出时钟；固定天气/白昼和减少动态偏好保留 | 环境清单与记忆清单共用相同契约；真实播放仍待实装验收 |
| 通用活动片段列表可能跨体型误选 | 每个角色增加`behavior_clip_bindings`，取角色白名单、活动、骨架和能力的交集 | 已列所需片段必须匹配骨架；最低活动无片段时必须指向本骨架的明确pose规格 |
| 26位特殊体型角色的52项待机/等待原先只有需求，没有最低表现规格 | 新增9族基础规格、18项静态pose和26份P3工单，全部52绑定均可解析 | 比较角色/骨架/行为/pose/工单；不把定格规格当成已完成动态，专有场景动作仍需逐章审校与制作 |
| Jim已有正确自身白名单，但通用护送列表仍包含轮椅待机 | 移除护送中的轮椅待机，移动/护送加能力门槛；保持Jim坐姿与上肢交接规格 | 禁止给该情境角色配置普通步行、护送、站起片段；不推断永久医学状态 |

## 3. 跨域字段与唯一权威

| 字段或内容 | 权威来源 | 美术如何使用 |
|---|---|---|
| `entry_id` | 词汇`occurrences.id`，适配表中为`occ-*` | 指向某册某词义的实际教材要求与证据，不自造美术词条ID替代它 |
| `lexeme_id` | 词汇`lexemes.id`，`lex-*` | 相同拼写的主册身份 |
| `sense_id / story_id` | 词汇`stories.id`，`story-*` | 相邻义项页及演出内容；不把story_id与NPC身份混用 |
| `content_revision / codebook_revision` | [词汇接入契约](../vocabulary/data/integration_contract.json) | 存入美术接口，来源更新后重新生成与校验 |
| `codebook_A`—`codebook_Z` | 词汇固定编码表，序章使用同一图像 | 一对一映射`mnemonic_anchor_A`—`mnemonic_anchor_Z`资源 |
| 原字形、大小写、附加符号和位置 | 词汇tokens与[主线适配条目](../vocabulary/data/mainline_entries.json) | 字体准确渲染，不用生成图片写字；原始表面位置与纯字母位置分开 |
| 词义、完整词音、分镜与提示内容 | 词汇审校流程 | 美术提供表现和操作，不自动把代表形象词音拼成目标单词读音 |
| 课程任务维度 | occurrence对应的`task_permissions` | 认读词不因动画而变成强制拼写；声音未就绪不产生听力通过记录 |
| 教材人物身份 | [textbook_characters.json](textbook_characters.json) | 每条来源身份只映射一个NPC记录；同名来源不自动合并 |
| 剧情演员与事件 | 主线事件使用教材人物ID，NPC表提供`npc_*`资源身份 | Lingling、Peter等按对应事件登场；Miss Li仍为游戏角色槽映射提案，不冒称原教材U1已指定她 |
| `root_location / storage_slot` | 词汇固定故事位置与义项页 | 作为持久内容索引，未提供物理绑定就放在故事册；不改公共地标 |
| 学习记录与奖励 | 主线/学习状态契约 | 动画只请求语义事件；任务层按唯一凭据提交；重看、跳过、恢复不重复奖励 |

`mnemonic_anchor_R`是字母R的机器人缩景；教材Robbie是有来源的角色身份。两者可以共享造型制作经验，但不能共用身份、日程或学习记录。其余地标动物同理。

## 4. 人物、动作和未完成量怎样读

当前来源表有142条教材来源内身份记录。NPC表包含这142条和熊叔、兔兔两位岛屿居民，共144条记录；另有5组未具名来源角色、6个拟议演员槽，4个当前功能称谓槽，以及Polly/Nano两个具名物件候选。后几类分别保留，不能相加成“已做出的角色人数”。

当前规格有40项动画片段：22项基础、11项Dino专用、7项轮椅情境；另有11种行为状态、12个骨架族和12项道具规格。新增9族基础表现规格内含18种静态关键姿势，26位特殊体型角色各两项最低行为，共52绑定，全部指向具体`planned_spec_id/pose_spec_id`，状态为`planned_explicit_pose_fallback_not_tested`。不存在仅保留空动作列表而把最低行为标为完成的条目。

52是角色×行为的绑定数，不是新增52个文件；18种定格也不计为动画片段。9族分别为犬、猫、象、鱼、灵长类、四足兔、四足怪兽、鸟、机械机器人。26份`special_action_work_orders`列出来源、骨架、基础姿势、必要语义、制作交付和P3章节发布前验收。原场景专有动作仍为`pending_corresponding_source_scene_editorial_review`，必须逐章落实，不能靠最低姿态宣称完整演出覆盖。所有模型、绑定、姿态文件和动画仍待生产，骨架兼容是计划，不是实测通过的证明。

人物核对的文本和代表页检查范围沿用来源报告：外观待核记录不能凭名字填充发型、肤色或服饰；142条也不是已确认互不相同的最终模型数。P3逐章交付时仍需处理来源内身份、跨册同名、未具名演员与章节场景绑定。

## 5. 样板需要真实验证的内容

P1先用`nose`检查词义与图像桥接，用`book`检查两个O独立实例，用`I'm`和`café`检查符号/重音，用最长节日词检查跨镜头接续，用`rain`检查冻结世界后教学演出仍可理解。另有`T-shirt`、`p.m.`、`No.`、`1st`、`Be careful!`、`from... to...`等结构化样例供接口测试。

输入、暂停、帮助、跳过、静音、减少动态、切场景和读档应在实际画面中走通。H0主动打开故事后不再当无提示；H3隐藏答案要检查真实界面；语音未到位时不能显示听力已验收。此轮没有运行这些交互，也没有验证儿童理解、动画品质或设备性能。

美术素材还需实际检查26代表物在游戏相机下的轮廓、完整蛋形的开合、符号字形、光照下的标准色、Dino翼尾、轮椅接触、非人形动作、天气遮蔽与夜间道路可读性。所有相关制作路径均为拟议输出，原始Blender源、COLOR_0颜色、已有UV通道、静态碰撞与SG锚点保持原状。

## 6. 复核与重新生成

`build_art_integration.py`读取当前主线、词汇适配表、场所清单与NPC规格，只写本目录的派生清单和能力矩阵。它不改词汇故事、教材资料、运行时或模型。源内容冻结后执行生成，再运行`validate_art_plan.py`。

静态核验包括：26图像映射、教材身份与NPC的一对一覆盖、动作骨架兼容与待补状态、词汇适配版本、20样例原样重构/重复实例/分镜/存放索引、来源文件指纹、计划状态、场景引用和本目录文档链接。来源一旦改变，指纹检查会要求重新生成，不把旧快照称作最新结果。
