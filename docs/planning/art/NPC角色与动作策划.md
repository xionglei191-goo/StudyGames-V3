# NPC 角色与动作策划

状态：**planning_only，资产与行为制作策划，尚未实现**。日期：2026-10-22。配套清单：[npc_animation_assets.json](npc_animation_assets.json)。

本稿把教材人物全部纳入首批 NPC 资产策划，再将熊叔、兔兔等岛屿居民和背景居民分层补充。首批资产覆盖与剧情登场顺序分开：后续单元出现的教材人物也列入首批，不必挤在三上 Unit 1 同时出场。新增模型、骨架、动画、道具、站位和日程均为计划内容；本轮没有生成、上传、下载或购买资产，也没有修改游戏。

## 1. 当前基础与制作边界

核对的当前工程为 0.4.0。`game/scripts/world_builder.gd::make_character()` 用球体、胶囊和方块组装玩家、老师、熊叔、兔兔，已有独立手臂与腿节点。`game/scripts/player.gd` 已通过程序做走路摆臂、呼吸起伏和 `wave/reach/kick` 短手势；不能把现状称作“完全没有动画”。当前这些角色还没有完整的蒙皮骨架、角色动画库或 NPC 日程系统。

`game/assets/world/manifest.json` 有熊叔、兔兔的主岛站点；`imported_interior.gd` 为果园、蛋糕坊、校园、教室、食堂、操场、足球场和专科教室配置了不同称呼的主持角色。许多地标目前共用兔型“邻居”，这只是可替换的占位表现，不是已经完成的独立人物阵容。

策划沿用现有 `village`、`home`、`school`、7 个校园子场景和 26 个 `landmark_A`—`landmark_Z`。不为 NPC 新建私宅，不改公共道路、建筑、门、固定记忆位置或碰撞轮廓。文中的家园门旁站位、欢迎角、桌椅使用点和合照点均须在制作阶段另加标记并验证，不能把计划标记当成现有节点。

**26 个代表形象仍是固定地标或记忆图像，绝不改成在岛上游走的任务 NPC。** 鸟巢、猫头鹰、星星等图像的语义和位置保持稳定；角色可以指向图像、陪孩子看图，不替代图像。

## 2. 阵容规模与美术共同规则

首批必须覆盖教材中核实的人物，不以原创同学 A/B/C 代替；教材姓名、物种和外形特征以实际书页证据为准。P0/P1/P2 仅表示动作和具体演出的制作顺序，不得把已核实教材人物移出首批。玩家模型是同一骨架试制的参照对象，不纳入本稿 NPC 人数。

- **轮廓：**人形与拟人角色延续圆润大头、短而可辨的四肢、低细节布料；为肩、肘、腕、胯、膝和脚留出真正可变形的结构。不能为追求大头而把肩和脖子完全藏住。非人形先保留教材物种和可辨结构，再做同一材质风格的适配。
- **识别：**每个主角同时有轮廓、配件和色块三种线索，不能仅靠换衣服颜色区分。兔耳、熊耳、发型与帽檐在游戏俯视角下仍须可读。
- **材质：**沿用温暖柔和、低金属感的材质语言；衣服以大色块为主，减少细密图案。人物的装饰色不承担唯一的语言答案线索。
- **动作：**幅度清楚、节奏温和；对话时手势有停顿，不持续抖动。表情先做目光、轻点头和简单口型开合；首批不承诺语音驱动的准确口型。
- **比例：**骨架试样以当前玩家脚底、门洞、桌面和交互距离为参照，再确定成人、儿童与拟人动物的相对比例。源图没有明确比较关系时，不凭姓名推断身高或年龄，不预设未经验证的米制高度。
- **画面验证：**分别看主岛远景、校园中景、对话近景及灰度截图。色彩教学情境用中性可辨照明，昼夜灯光不能改变颜色答案。

## 5. 首批共享动作库

P0 是序章与三上 Unit 1 的动画闭环：待机、行走、问候、说话/倾听、指向、递接、从台上取物、放物、合照。P1 补上生活与课堂，P2 增加特色。不是为每位 NPC 单独制作一整套相同动作；同一动作通过幅度、节奏、手势侧别和道具配置做少量受控变化。

| 动作 ID | 级别 / 循环 | 用途与关键要求 | 语义时点 |
|---|---|---|---|
| `idle_relaxed` | P0 / 是 | 稳定脚底、呼吸和少量目光；可有静态休息姿势 | 无剧情提交 |
| `walk_in_place` | P0 / 是 | 原地走路循环，由移动控制器位移；根据真实速度调步频 | 脚步只供声音/效果 |
| `greet_wave` | P0 / 否 | 手抬起后留可读停顿，熊爪/兔手均可看清 | `gesture_apex` 仅视觉 |
| `talk_gesture` | P0 / 是 | 两三种轻手势交替，避免把每个音节做成摆臂；语音独立 | 无口语评分或剧情提交 |
| `listen_nod` | P0 / 否 | 目光朝向对方，点头不代表答案正确 | `gesture_apex` 仅视觉 |
| `point_target` | P0 / 否 | 指向目标方向；高低目标由有限姿势/瞄准校正处理 | `target_revealed` 只请求高亮 |
| `give_item` / `take_item` | P0 / 否 | 成对交接，双方到位后才播放；邀请、生活册和装饰共用 | `handoff_ready` 请求事件控制器核对并提交一次 |
| `pick_up_table` | P0 / 否 | 从桌面/柜台拿物；先只支持已验证的高度范围 | `grip_contact` 请求挂接道具 |

| `write_table` | P1 / 是 | 与桌高、座姿、纸笔匹配；不把写字表演当成拼写掌握 | `pen_contact` 仅效果 |
| `pick_up_low` | P1 / 否 | 屈膝取低处物品，和台面取物分开；避免简单弯腰穿模 | `grip_contact` 请求道具挂接 |
| `walk_carry` | P1 / 是 | 持物走路，手臂保持物品、腿走路；不能让书穿胸 | 无剧情提交 |
| `cheer_soft` | P1 / 否 | 小幅举手或拍手，明确祝贺共同成果而非每次答题 | `gesture_apex` 仅视觉 |
| `warmup_touch_head` | P1 / 否 | 对应三上 Unit 6，手触头顶须按实际比例修正 | `gesture_apex` 仅示范，不检测儿童现实动作 |

| `water_plant` | P2 / 是 | 园艺闲忙动作，壶是计划中的道具；不是序章 A/F 必做步骤 | 水线效果不提交序章进度 |

所有时点采用语义名称，具体落在动画第几帧须在导入和回放后确定。循环动作不能反复发放物品。跳过、掉帧、暂停、读档和转场均不能靠“动画播完一次”重复结算；事件控制器以唯一事件凭据和当前任务条件确认事实。辅助完成、看示范、独立完成由任务交互记录，不能从动作播放推断学习效果。

Dino 另列 `dino_` 前缀的 11 个 P0 同语义动作，使用 `dino_special_v1` 专用骨架候选（对应来源建议 `dino_winged_v1`）。比如 `dino_give_item` 与 `give_item` 都通知同一交接事件，但姿态、接触范围与动画曲线独立制作。若教材形体不能稳定手持，采用可读的台面交接动作，不硬拉前肢做成人形握物。

Jim 的教材情境另列 `wheelchair_` 前缀的 7 个坐姿动作：待机、招手、说话、倾听、指向、递出与接过。轮椅座面、扶手和礼物接触需要验证；不默认套普通步行动画，能力描述以原文为准，不从画面推断永久医学状态。轮椅移动若剧情需要，另定轮速与移动控制，不能靠播放步行片段实现。

清单因此包含 **40 个动作规格 = 22 个基础条目 + 11 个 Dino 专用条目 + 7 个轮椅情境条目**，不是已有动画数量。其他教材生物/机器人按人物源表保留必要语义动作与专用族评审，未完成接触与形体审查前，不把待机、游动或机械关节行为虚标成已取得的动画文件。

其余26位特殊体型角色的最低表现现已具体化为**9类基础规格、18项静态关键姿势、26份P3动作工单**。每族有`idle`稳定待机和`event_wait`安全等待各一项姿态，52个角色×行为绑定均通过`planned_spec_id/pose_spec_id`指向实际规格，状态为`planned_explicit_pose_fallback_not_tested`。源文件仍待制作；这些定格不算新增动画片段。

| 特殊骨架族 | 稳定待机/安全等待的最低表现 | 不能由基础姿态推定的能力 |
|---|---|---|
| 犬类四足 | 四足支撑、自然头尾；头部朝向对象等待 | 人形挥手、递接或已完成步态 |
| 猫类四足 | 来源允许的四足/坐伏支点、尾部无穿插；保持支撑看向对象 | 直立人形动作、自动抓挠或追逐 |
| 象类四足 | 四足承重、象鼻自然；稳定注意姿态 | 象鼻交接已可用、可套人手挂点 |
| 水中鱼类 | 水中体轴和鳍形完整，朝向对象时不漂出水域 | 陆地步行、已制作游动片段 |
| 灵长类 | 按源图确定支撑和尾部，保持支撑表达注意 | 未核验的直立站姿或抓握 |
| 教材四足兔 | 原图四足/坐伏姿态、耳尾清楚；稳定看向焦点 | 与岛屿拟人兔兔共用身体与权重 |
| 故事四足怪兽 | 按Nian原图保持支撑与角尾轮廓；安全距离等待 | 自动追逐、冲撞或扑向镜头 |
| 鸟类 | 源场景支点上栖息、翼收拢、爪部接触；朝向焦点 | 默认飞行、跨岛漫游 |
| 机械关节机器人 | 依Robbie源图设置支撑与硬壳关节中性姿态，显示面/头部朝向对象 | 未测机械指向与道具交接 |

每份工单保留教材来源、骨架、两项基础姿态、必要动作语义、章节发布前置条件和实际镜头验收。原场景的专有动作、移动、飞行或游动仍需逐章拆解与制作；最低定格不能替代章节必要动作完成。未核验外观或动作的角色仍属于首批覆盖责任，不能以“有pose规格”提前批准模型或章节发布。

## 6. 骨架与 Mixamo / Tripo 使用方式

首批先验证**一套共享双足人形骨架规范**，含身体、头、双臂和双腿。儿童、成人、熊、兔可以共用骨骼语义与动作来源，但比例、骨骼静止姿态、蒙皮和道具接触需要各自校正。共享规范不等于把一份权重无修改套到所有体型。

当前来源清单对应 12 个候选骨架族：人形、Dino、轮椅情境人形、机械关节机器人、犬、猫、鸟、象、鱼、金丝猴、教材四足兔及 Nian 怪兽。这是按必要体型归类的计划，不是为每个地标做一套骨架，也不是 12 套资产已完成。Robbie 的硬壳与关节须防穿插，鱼不播放陆地步行，教材四足兔不等同岛屿拟人兔兔；六只具名鸟尚有名字与个体羽色对应待核，不能随意把群图颜色分配给名字。

建议先用一位普通人形同学跑通 `idle/walk/wave/point/give/take/sit`，再试熊叔与兔兔。现有由独立几何体拼出的角色不是可直接送入 Mixamo 的已清理蒙皮网格。熊兔的拟人模型必须有清楚的头、躯干、手臂和腿，肢体不要粘连；大帽子、长耳、尾巴和手持道具先分离处理。若拟人比例仍不适配，使用 Blender 绑骨/权重与动作修正，不因此改变角色身份或让主线等待服务可用。

耳、尾、衣摆是可选的附加骨或局部辅助动画，不要求 Mixamo 自动生成。地标中的鲸鱼、四足斑马、固定猫头鹰形象、道具机器人与建筑机械各有不同结构：地标表现本期保持静态或简单节点动画；只有后续玩法确有需要时才另建专用骨架。这条范围约束不排除教材中已核实的同物种角色，教材角色仍按自己的身份进入首批并单独评审。

Mixamo 的账号/地区可用性是制作前依赖，当前未登录验证。Adobe FAQ 目前列有中国国家/地区代码账号不可用限制；不能预设本机或账号一定能用，也不设计绕过方式。来源、动作名称、下载日期、骨架映射、改动记录和授权条款快照随以后实际取得的资产保存，本稿所有资源路径均为空或明确为规划。

以后用 Tripo 替换更复杂造型时，保留原始输出和制作记录，经过清理/必要重拓扑、UV/材质、静止姿态、蒙皮、重定向和 Godot 回放，再替换当前视觉层。Tripo 可提供相关绑定能力不代表当前每个模型可直接复用现有动作；即使标注 Mixamo 风格骨架，也要核对骨骼静止姿态、比例、关节位置和导出缩放。详细来源与加工链由同目录美术管线文档统一维护。

## 7. 动作控制与 NPC 日常

下面是待实现的接口约定，不代表当前代码已有这些节点。

- `AnimationPlayer` 保存动作资源；启用 `AnimationTree` 后由它统一控制同一套骨骼的切换与混合，避免二者或 Tween 同时写同一骨骼。道具小动画可独立控制，不夺取身体位姿。
- 首批日常移动使用 **in-place**。角色控制器处理寻路、速度、朝向和简化碰撞，动画依实际位移调步频。检测零位移时停止走路，避免贴墙原地滑步。
- Root motion 留给后期经验证的短演出。若采用，必须由唯一控制器消费根位移并经碰撞处理，不再叠加普通移动速度。不能混用两套位移导致角色漂移。
- 递接、取放、坐写使用明确交互点与道具挂点；精确接触可后期加有限 IK。共享动作重定向后逐体型核对，不能靠大范围拉伸手臂遮盖比例错误。
- 人物朝向沿用当前角色面向 `+Z` 的约定。导入转换在视觉根层统一处理，不在每段动画或每次交互临时补不同旋转。
- 当前 NPC 的名字标签、静态障碍与外观分开创建；将来让 NPC 移动时，标签、交互锚点和简化碰撞必须随演员实体同步，交互查询也要使用演员当前位置，不能仍指向旧静态标记。

建议状态：待机 → 走到站点 → 看向交互对象 → 对话/演动作 → 返回日常。成对交接、同行、坐姿工作、事件等待和离屏轻量状态单独管理，定义见 JSON。

**日程由故事时段驱动，不绑定现实钟点。** 上午迎接、上课、课后、晚段只是可恢复的剧情时段。U1-01 必须使用清晨情境，不能在夜景里仍说 `Good morning.`；玩家何时打开游戏都可进入该事件。

世界时钟与演出时钟分开：对话、记忆和教学界面打开时，**全部 NPC 的日程与背景移动都暂停**，包括远处和离屏日程；当前演员必要的对白、表情及教学示范可以通过独立演出时钟继续。暂停菜单打开或应用进入后台时，两套时钟都停。不能只停面前的演员，却让背景居民继续赶路或收工离场。

优先级为：安全恢复/转场 > 已锁定主线演出 > 玩家主动交互 > 日常工作 > 背景漫游。预约角色、道具和使用点后再开演；取消后释放预约。同行角色在近处等待落后的玩家，不催促，不把玩家推离道路；导航失败可在遮挡转场/重新进入时回到已核验的站点，不能穿墙直线追赶。

一位角色只有一个世界身份。`village` 的熊叔与 `landmark_C` 的熊叔是同一人，切换场景后依据剧情状态决定呈现位置，不能生成两份进度。校园/教室老师同理。背景角色避免占门、狭桥和记忆点；互动中的主角保留稳定站位，独立简化碰撞不跟随挥手手臂放大。

离屏 NPC 仅在世界时钟运行时更新逻辑所在场景和日常状态，不播放完整骨骼，也不在离屏自动完成需要玩家看见的序章示范、交接或教学任务。进入场景后恢复合理待机姿势；需要玩家回应的事件等待玩家。存档保存身份、逻辑场景、故事时段、活动/交接状态和已提交凭据；不依赖保存某一帧骨骼姿势恢复事实。

减少动态设置下保留必要的动作起止与关键姿势，关闭大起伏、频繁背景摆动和额外欢呼；玩家可以点选或直接看示范。合照、递接和任务事实仍由同一事件确认路径完成，不能因为省略动画丢失奖励，也不能因静态替代误记为独立学习完成。

## 8. 主线动作组合与交付顺序

| 范围 | 人物与动作组合 | 复用点 / 制作依赖 | 完成边界 |
|---|---|---|---|
| H01–H04 家园操作 | 熊叔问候 → 指地图 → 递册；玩家接册 | 复用当前家园/主岛；册子、手部挂点和门旁演出点待制作 | 建立操作体验；动画不生成英语掌握记录 |
| 26 字母序章 | 向导指固定形象 → 等待短互动 → 展示发现页 | 共享指向/问候/待机；很多轻操作仍在卡片层完成，不逐站扩展 3D 动作 | 实际到访+有支持体验；不能离屏自动勾完 |
| U1-01/02 | 熊叔清晨问候、递邀请；短距离同行或指路 | 沿用现有场景与地图；连续跟随/邀请道具待实现 | 路线到达与语言证据分开 |
| U1-03/04 | Lingling 自我介绍、带到欢迎角；教材教师指卡；同伴/玩家放名牌 | 教材人物模型、名牌、欢迎角均待制作；Aa/Bb/Cc 使用已固定图像 | 自报昵称与字母复现单记；装饰选择无对错 |
| U1-05 | 已核实教材同伴取物 → 递给玩家 → 玩家接 → 感谢与回应 | 取/递/接三段共享；双方站点和道具唯一持有者要核验 | `Thank you.` 来自实际帮助情境；只看动作不等于掌握表达 |
| U1-06 | 伙伴待机或指生活册，返回原事件 | 可选词汇故事模块；不新增强制 NPC 演技关卡 | 可跳过；没有已审校条目就不表演默认故事 |
| U1-07/08 | 兔兔再次问候 → 众人各就各位 → 合照姿势 | 共享走路/问候、轻变体合照；站点和相机待制作 | 合照仅提交 U1-08 照片成果，不提前完成整章 |
| U1-09/10 | 玩家放照片；之后兔兔/其他熟人来访 | 共享放置；家门访客点待制作，不能堵出口 | U1-09 才结算章节；下次来访不冒充已发生真实延迟 |

制作顺序：先核实全部教材人物并列入首批 → 人形样机与共享骨架规范 → P0 的 11 个动作条目及道具对齐 → 熊叔/兔兔和教材特殊形体的比例验证 → 按章节安排首批人物演出 → P1 坐读写和体育/食堂 → P2 特色动作与复杂 Tripo 造型。动作先后与章节出场顺序不得缩减首批教材人物覆盖。若动画制作尚未完成，可使用当前程序手势或静态关键姿势承接演示；这是一条计划中的渐进替换路径，不等于本轮已经接入。

进入实际制作后，P1分别核验人形、拟人动物、Dino、轮椅情境四类样板；只有可步行角色检查走路脚底，轮椅情境检查坐姿、脚踏与礼物接触。再检查主岛门口、欢迎角、狭窄室内和足球场的真实视角。P2先接通完整26字母序章与U1，P3按八册章节补齐全部首批来源身份；不是先完成全部142条模型才能做首章。演出需覆盖取消、暂停、切场景、读档、静音与减少动态；动作和外观通过检查后仍需独立确认任务记录。当前交付只检查策划 JSON 的标识与引用一致性，不宣称完成骨架、动画、性能或儿童试玩验收。

通用活动不是跨骨架通用曲线。结构化`behavior_clip_bindings`对每个角色、每种允许活动列出兼容片段或上述明确的静态姿态；活动同时检查骨架及能力。每项最低活动必须有可解析的规格，不静默播放人形待机。Jim自身白名单原本已排除普通步行与护送，本次再从通用护送列表移除轮椅待机并添加能力校验，避免后续接线误选。
