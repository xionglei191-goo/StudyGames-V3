# 连贯故事扩写 v2 作者约定

用户2026-10-23反馈：单词故事不够通顺，需要调用想象力，完整扩展。范围为全部1096个核心故事与46个补充义项；旧版已只读归档。只编辑本目录分配的稿件，禁止改教材、游戏、主线、美术与既有稳定ID。

每位作者读取自己的 `input_*.json`，逐条创作 `output_*.json`，顶层为数组。每条格式：

```json
{"id":"story-...","title":"有趣而具体的故事名","beats":["第一格的完整故事句。","第二格紧接发生的完整故事句。"],"meaning_bridge":"用故事中发生的具体结果解释当前词义。","recall_question":"围绕具体物品或变化，邀请孩子想出下一步的问题？"}
```

`beats`恰好等于输入steps数量，顺序一一对应字母位置。每个beat至少一句完整中文，明确本格固定形象作为该格的行动者；可以带上一步的结果或介绍下一步，不能让下一字母角色抢走当前动作。重复形象用“第一只/第二只”等明确区别。全文直接连接所有beats即可成为流畅的小故事，不依赖表格才能看懂。单词短，故事可以短，但不是“拿出、托住、照亮”清单。通常每格25–45字；单字母词写一段45–80字；超长词可每格18–30字，分镜帮助阅读。

先想整个故事的生活问题或小愿望，再依次安放固定形象。每篇有清楚起因、连续行动和贴合词义的结尾，至少一处可想象的声音、触感、变化或有趣意外；无需每个故事都出现事故或奖励。新写法要清楚解释物品怎样从甲到乙、为什么要做下一步。读起来应有自然的时间和因果，不要机械逐句加“然后、接着、最后”，不要把旧短动作加统一开头结尾冒充扩写，不得套全库统一桥段。

同一个具体物件或任务贯穿全篇。尽量沿用输入固定存放位置与核心意象，允许为修复逻辑而改动作；不改词义、ID、字母映射或顺序。扩写是同一版本的统一编辑修订，跨册仍只共用一篇。补充义项另写完整片段，保持与主故事相邻的画面；当前meaning才是本条义项。`meaning_bridge`不能只写“目标义项……本故事体现……”的空话。

可以拟人、缩放、飞行、温柔的奇幻。A苹果、B小船、C蛋糕、D鼓、E蛋壳（完整蛋形）、F花朵、G地球仪、H帽子、I冰淇淋、J罐子、K风筝、L灯笼、M蘑菇、N鸟巢、O猫头鹰、P南瓜、Q拼布被、R机器人、S星星、T火车、U雨伞、V火山、W鲸鱼、X木琴、Y毛线、Z斑马，不可换成其他同首字母对象。Egg仍是蛋形，不写碎壳代表鸡蛋的词义。其他道具可以存在，但只给本格形象编码，不擅加额外字母。

功能词通过明确指代、时态、数量或关系演出来，不能只拿写着英文的牌子；专名保持身份，不杜撰地理历史与词源；英文例句须语法正确。故事不是发音规则、真实教材人物经历或学习效果证据。与真实家庭、身体、国籍有关的词不靠刻板印象解释。

逐条人工式撰写，不使用随机生成或按关键词套模板的文本程序。允许用脚本把手写TSV/JSON转换为文件和验证条数。每批约20–35条可写入一个part文件，最终合并为output_*.json；辅助文件以自己的g4/g5/g6/root前缀命名。请持续推进全部分配条目，不能只交样例。完成后检查ID集合、字母数、每句主角及语义连接，报告实际检查范围；人类编辑与儿童试用继续pending。
