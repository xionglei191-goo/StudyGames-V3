# 小学英语故事线与关卡内容设计

> 版本：v0.1  
> 日期：2026-05-24  
> 适用阶段：英语主线内容扩展  
> 内容来源：`docs/小学英语重点分析` 中三年级下册至六年级下册的重点整理  
> 使用原则：先将 `docs/小学英语重点分析` 中整理出的单词、句子和原文行完整进入游戏内容库，确保可检索、可引用、可追踪；再在此基础上做原创剧情包装和扩展任务。

## 1. 设计目标

下一阶段英语内容要从“单个生活任务”升级为“可连续推进的故事主线”。孩子不应感觉自己在刷题，而是在小镇中帮助朋友、探索场景、完成活动，并自然使用本单元的词汇、句型和语法。

本设计文档用于指导以下工作：

1. 把 7 册英语重点资料拆成可开发的章节、关卡和任务。
2. 让每个 Unit 都对应一个明确剧情目标、语言目标、语料引用和互动玩法。
3. 保留 StudyGame 现有“原创时尚娃娃风小镇 + 生活委托 + 家长可解释”的产品方向。
4. 为后续配置化任务、资源制作、AI 辅助出题和家长报告打基础。

## 2. 总体故事设定

### 2.1 世界观

游戏发生在原创的“星光小镇”。小镇中心有一座会发光的“故事钟塔”，钟塔连接着校园、花园、厨房、邮局书房、商业街、剧场、自然馆、旅行站和星空馆等区域。

某天，钟塔里的“英语星片”散落到不同地点。每一片星片都封存着一种生活表达能力：问候、时间、天气、喜好、数量、位置、规则、计划、过去经历、未来安排、健康建议、旅行介绍等。玩家需要跟随小镇伙伴一起完成委托，收集星片，让小镇重新亮起来。

### 2.1.1 总故事线：修复七段星路

当前 75 关不再只是按教材 Unit 排列，而是被包装为一条完整的“七段星路”：

1. 故事钟塔失去 7 段语言光谱，小镇区域随之变暗或失序。
2. 玩家作为新搬来的孩子，被 Keeper Ray 邀请成为“星路修复员”。
3. 每个 Chapter 修复一段星路，Chapter 内的 Unit 是一次次生活委托。
4. 每完成一个 Unit，玩家获得一个星片奖励，并让对应场景产生可见变化。
5. 每完成一个 Chapter，对应区域完成一次阶段性修复，并解锁下一幕。
6. 最终 7 段星路汇成“毕业旅行星图”，玩家把小学英语阶段的表达能力用于一次世界名胜分享会。

这条故事线的设计重点是让孩子始终知道“我为什么继续下一关”：不是为了刷完 Unit，而是为了让小镇从认识朋友、进入校园、筹备节日、独立处理城市委托，一步步走向旅行分享和毕业收束。

## 3. 核心玩法循环

每个 Unit 按“剧情委托 -> 语言任务 -> 场景变化 -> 星片奖励 -> 回访任务”推进。

| 步骤 | 儿童体验 | 系统内容 |
|---|---|---|
| 接到委托 | 角色用一句话说明要帮什么忙 | `introCopy` + 场景入口 |
| 找线索 | 点击场景锚点、观察物品或人物 | 词汇识别、图片匹配、阅读线索 |
| 做决定 | 选择、拖拽、排序、配对或路线点击 | 句型和语法在行动中出现 |
| 看到结果 | 物品归位、角色出发、活动开始 | 成功反馈、温和重试提示 |
| 收集星片 | 获得词汇卡、句型卡、装饰或服装 | 奖励配置 + 进度记录 |
| 轻回访 | 后续任务中再次遇到旧知识 | 间隔复习和家长摘要 |

## 4. 任务模板库

| 模板 | 适用语言点 | 交互形式 | 示例任务 |
|---|---|---|---|
| 找到正确物品 | 词汇、颜色、服饰、食物、职业 | choice / drag | 选出 `raincoat`，把 `yellow shoes` 放到镜子前 |
| 对话补全 | 问候、请求、点餐、建议 | choice / match | 朋友说 “How are you?”，选合适回应 |
| 场景定位 | 方位介词、路线、地点 | choice / click-map | 根据 `under / beside / near` 找物品 |
| 计时与日程 | 时间、星期、作息、课程 | order / choice | 安排一张上学日时间表 |
| 数量清点 | 数字、How many、得分、序数词 | choice / count | 数风筝、算班级得分、排比赛名次 |
| 步骤排序 | 制作、研究、节日准备 | order | 做风筝、做卡片、写报告 |
| 规则判断 | Don't、should、sign means | choice | 图书馆里哪些行为不合适 |
| 观察动作 | 现在进行时、情绪状态 | choice / match | 判断谁正在擦窗、谁正在包粽子 |
| 行程规划 | 交通、问路、将来时 | click-map / order | 去博物馆、酒店、邮局的路线 |
| 回忆相册 | 一般过去时 | order / choice | 选出昨天/上周发生的事 |
| 比较选择 | 比较级、最高级 | choice / sort | 哪只鸟更大，哪本书更有趣 |
| 小报告生成 | 综合语篇、家长可解释 | match / order | 完成旅行介绍、环保海报、健康建议卡 |

## 7. 内容写作规则

1. 儿童端每次只出现一个明确行动目标，避免一屏塞满教材知识。
2. 教材重点文档中的句子和单词必须先进入语料库，关卡通过语料 ID 引用；儿童端可以按任务节奏分批展示。
3. 每个关卡最多突出 2-3 个核心知识点，其他词汇和句子已进入 Unit 级“教材库”，并可通过回访卡和拓展任务继续复现。
4. 错误反馈要提示线索，不使用“错了”“失败”等压迫表达。
5. 同一语言点至少在主线、回访、奖励卡中出现 3 次。
6. 三四年级侧重图像匹配和短句，五六年级逐步增加短语篇、计划和报告。
7. 家长端可以明确写“练习了什么句型/语法”，儿童端尽量写成任务目标。

| 邮局书房 | 全篇章补充 | 阅读、研究、信件、相册、故事、电脑、回忆 |

每个可玩主题场景当前已落地 3 个教材素材组，并在 `src/content/scenes.js` 中通过 `materials` 配置维护。地图面板会汇总 8 个主题场景承接的关卡数量，教材库会随 Unit 展示对应场景素材，Phaser 房间会在场景上方显示可点击的素材栏。当前已经生成专属 PNG：新增场景背景、主题锚点、24 个教材素材图标、75 个主线奖励图标都写入 `src/assets/images/manifest.txt`，可通过 `scripts/generate-theme-assets.mjs` 本地重建，也可通过 `scripts/generate-full-refresh-assets.mjs --write-prompts-only` 维护后续 AI 美术刷新 prompts。

## 9. 开发落地顺序

1. 扩展内容模型：增加 `chapterId`、`unitId`、`storyArcId`、`prerequisiteTaskIds`、`reviewTaskIds`。
2. 增加主线地图：按篇章展示章节进度，当前已支持 7 册 75 关。
3. 扩展英语知识点配置：从现有 `kn_eng_g3_*` 扩展到按册和单元命名。
4. 制作任务模板：优先完善 `choice`、`drag`、`order`、`match`，再做地图路线点击。
5. 建立内容审核表：每个关卡检查儿童文案、家长解释、语言点、资源需求和安全边界。
6. 完成垂直切片试玩：观察儿童是否理解“故事推进”和“语言任务”的关系。
7. 再批量生产剩余 Unit：先三下和四上，再进入五六年级复杂语法。

## 11. 家长报告映射

| 阶段 | 家长可见能力描述 |
|---|---|
| 三年级下册 | 能把基础英语表达和日常生活动作联系起来，例如问候、看时间、看天气、数数量、说交通方式。 |
| 四年级上册 | 能在校园和家庭场景中使用简单句描述场所、喜好、能力、规则和物品归属。 |

## 12. 风险与注意点

1. 75 个 Unit 已进入运行时主线，后续扩展要继续依赖内容表和校验脚本守住语料覆盖。
2. 五六年级语法抽象度更高，需要更多语篇和步骤型任务，不能只做单词点击。
3. 全量语料进入游戏后，需要建立覆盖追踪，防止只做了故事扩展却漏掉基础单词和句子。
4. 部分节日和国外文化内容要保持中性介绍，不做消费诱导。
5. 儿童端不要出现长篇语法解释，语法说明放到家长端和内容审核表中。
