# P1 本机原生性能结论

正式记录有效：12 / 12 阶段完成，6 / 6 开关配对可比，原生运行时错误为 0；每阶段预热 10 秒、采样 60 秒。

设备：AMD Ryzen 5 3600 6-Core Processor（12 逻辑处理器），NVIDIA GeForce RTX 4070，驱动 610.88，Microsoft Windows 11 专业版（build 26200）。原生窗口 1440×900，内容输出 1440×900；Godot 4.7.2-stable (official)、gl_compatibility、4× MSAA。

测量使用调试引擎运行实际产品主场景，关闭 VSync 且不设 FPS 上限；这是固定镜头环境开关对照，不是导出 EXE 在默认设置下的帧率承诺。测试夹具允许后台继续渲染，但实际前台/后台比例由 Windows 只读采样单独记录。

本次共记录 194,678 个原生帧间隔与 2,871 个阶段内 Windows 进程样本，Windows 样本全部显示游戏处于前台，不能据此声称已测后台性能。环境目标分别为果园 20 个树冠/1 个水面、主岛 162 个树冠/3 个水面、校园 54 个树冠/0 个水面；校园配对只覆盖风。校园还保留了 3 个 LivingWorld 角色样板；其他场景原有居民照常保留。

## 有效性与范围

- 同一设备、镜头、天气晴天、日间和种子；顺序为关→开、开→关。无暂停、最小化、相机漂移、结构变化、演员生成失败；运行前后源文件摘要和生产存档均一致。
- 环境关闭仅复位树冠、撤除水面覆盖材质并隐藏雨；演员、照明/雾、时钟和资源分配保留。清天的增量是风与水展示成本，不是整套天气总成本，也不是卸载资产可节省的内存。
- 根视口渲染 CPU 和根视口 GPU 是独立计时，均不是整个进程全部 CPU/GPU 成本。TIME_PROCESS/PHYSICS 是每秒缓存峰值，其采样分位只能作为诊断，不能解释为逐帧 CPU 分位或预算通过；本机同 commit 的实现见 [Godot main.cpp](https://github.com/godotengine/godot/blob/ed1daf0bf/main/main.cpp#L4723-L4761)。截图/装载峰值可滞留在监视器缓存，本报告保留该列但不作成本结论。
- 记录器在内存中缓存逐帧行，因此进程内存包含采集开销与分配器/资源缓存波动，不等于成品启动占用。
- 三角形来自可见场景树中网格拓扑，包含屏幕外网格，不含 MultiMesh 和重复渲染遍；GPU 的顶点/索引监视器没有被冒充成三角形。
- RSS、私有提交和显存使用量独立报告。显存物理容量见 [nvidia-smi 补充记录](hardware-vram-confirmation.json)，没有使用 Win32 AdapterRAM 的受限字段推断。
- 当前机器、GL 配置和清天样区之外未测：低/标准/高预设、其他设备、四天气×四时段×房间×分辨率、移动玩法或词故事的性能。当前记录不代替指定目标硬件预算验收。
- 截图和 PNG 序列均在计时以外。目标为每场景 20 秒/4fps，但主岛的 81 帧实际捕获耗时 37.235 秒、世界时钟推进约 8 秒，受读回/编码开销和单帧时钟上限影响；这是原生采样序列，不是固定频率实速视频。正式计时没有使用无界面模拟、固定 FPS 或人为帧延迟。
