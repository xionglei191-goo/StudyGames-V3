## 已实现的交互

### A 果园：真实拿取、搬运和入篮

入口有两条：新存档完成熊叔的 H01—H04 出门准备后，选择「请向导陪我去苹果屋」；已经开始旅程的存档也可从旅行册选择「和兔兔一起采苹果」。引导会先走到 A 的既有学习锚点，再接管兔兔活动。

点低枝苹果或「摘苹果」后，兔兔沿可走路线靠近，手部接触苹果才提交拿取；点篮子或「放进篮子」后，兔兔持物移动，在篮口接触时提交放置。苹果随后落入篮内，出现 Aa / Apple 发现卡。字母与单词读音各有按钮，点「收下这次发现」才返回发现结果页。

活动支持「请兔兔示范」「暂停 / 继续」「下次再来」和发现卡中的「再玩一次」。存档分别保存待拿取、已携带、已入篮状态和当前轮次；退出重进恢复已确认状态，重复回执不会重复推进。示范方式在拿取时开始记录，同一轮后续动作不能把已观察到的帮助降回独立完成。

保存失败时先保留物品当前归属：拿取未提交成功，苹果仍在枝头；放置未成功，兔兔仍拿着苹果。恢复写入后通过「再试一次」继续。活动开始会保存玩家的可见性与碰撞状态，接管兔兔后隐藏玩家；结束时恢复原值。引导到达位置与兔兔出生位置靠近的情况已经纳入真实旅程回归。

这项发现活动不增加旧生活委托的背包苹果或叶币。原有每日三颗采集、交付委托与制作蛋糕保持独立；A 发现完成也不写成英语独立掌握。

### 词故事：可播放的动作与可恢复位置

故事面板提供「播放故事 / 继续播放」「暂停」「再看一次 / 再播放」「逐步看」。关闭后保存分镜、字母位置、动作进度及提示历史；重新打开时停在保存姿势，手动继续。切到后台会暂停；减少动态使用开始、中间、结束关键画面，保留动作含义和顺序。

| 专属样例 | 已制作的动作链 | 核验重点 |
|---|---|---|
| `hello` | 抬帽问好、蛋壳探头、两盏灯接续光线、猫头鹰招呼 | 长词跨页、两个 L 的独立位置 |
| `nose` | 鸟巢摇出猫头鹰、大鼻子托星、喷嚏送星入壳、壳上留下鼻子印 | 画面与鼻子含义相连，移动物件实际到达接触位置 |
| `book` | 小船运书、第一只猫头鹰打开封面、第二只翻页、风筝托书 | 两个 O 各自做不同动作，书的开合和运输可见 |
| `football` | 踢球、接球、传球、火车/小船运输、苹果踢球、近远门灯引导入门 | 八个字母按原位分两页，球的连续传递 |

其他词条从已有动作文本生成照亮、展开、滚动、飞行、接住、搬运等结构化演出。全词库可以调用这一组件，但只有上述四组为本轮专属动作链；其余仍需逐词编辑和语义审校。当前舞台为二维图像演出，不能描述为每词已经完成独立三维动画。

每页最多四个字母演员；重复字母按原位置实例化。H0/H1 不实例化演员舞台，H3 只加载已揭示位置的图片，隐藏动作中可能泄露相邻字母的说明。记录动作提示以实际可见绘制为依据，隐藏播放不伪造展示事件。播放位置本身不增加帮助或掌握；实际提示与作答由状态层分别记录。

### 四类角色动作样板

教材人形、已有拟人动物、Dino 与 Jim 轮椅情境分别检查。普通步行角色有走路、招手、递接和取放；Dino 使用独立翼尾姿势；Jim 保持坐姿和脚踏支撑，拒绝站起、普通步行与地面拾取动作。暂停、后台和减少动态均参与逻辑检查。

角色动作来自保存关键帧与刚性骨骼部件，手部挂点和语义接触事件分开处理。重播可以重现视觉接触，同一事件键不重复产生语义回执；奖励仍由玩法状态层确认。

[原生视觉核查](../../../assets/characters/p1/validation/视觉核查.md)已保存 364 张 PNG、8 段 GIF 与 2 张关键帧拼图，覆盖 Peter、Lingling、兔兔、Dino 和 Jim。可直接查看 [兔兔取果](../../../assets/characters/p1/validation/rabbit_pick.gif)、[兔兔放篮](../../../assets/characters/p1/validation/rabbit_place.gif)、[Dino 招手](../../../assets/characters/p1/validation/dino_wave.gif)和 [Jim 接物](../../../assets/characters/p1/validation/jim_take.gif)。这些样片在校园接触检查场景采集，真实果园的遮挡、路线和回执由果园集成证据另行覆盖。

![Dino 与轮椅样板关键帧](../../../assets/characters/p1/validation/dino-wheelchair-actions.jpg)

## 性能实测与复现

**正式记录有效：12 个阶段、6 组开关配对均通过有效性核验，原生运行时错误为 0。** 主岛、校园、果园分别在同设备、1440×900、固定镜头下比较环境动态关闭/开启，每阶段预热 10 秒、采样 60 秒，重复两轮并交换开关顺序。测试设备为 Ryzen 5 3600、RTX 4070、驱动 610.88、Windows 11 build 26200；使用 Godot 4.7.2 的 GL Compatibility 与 4× MSAA。

下面将每个场景动态开启的两轮原始帧合并后重新计算分位数，单位为毫秒：

| 场景 | 帧时 p50 | 帧时 p95 | 帧时 p99 |
|---|---:|---:|---:|
| A 果园 | 2.731 | 3.482 | 3.920 |
| 主岛 | 4.699 | 5.775 | 6.568 |
| 校园 | 4.115 | 4.984 | 5.512 |

完整开关对照、CPU/GPU 不同口径、内存与原始 CSV 见 [正式性能报告](../p1/performance-20261022-193930/performance-review.md)和[机器可读汇总](../p1/performance-20261022-193930/summary.json)。源文件、正式存档、固定结构与配对负载均保持一致。测量使用调试引擎运行实际主场景，关闭 VSync、解除帧率上限；结果只适用于这里的晴天固定镜头环境对照，不是默认导出成品帧率或其他设备的承诺。

在仓库根目录运行：

```powershell
python -X utf8 scripts/verify_p1.py inventory
python -X utf8 scripts/verify_p1.py performance --rooms landmark_A,village,school --repeats 2 --allow-background --motion-seconds 20
```

正式采样使用独立原生 GPU 夹具，允许后台持续渲染，不修改正式游戏的失焦暂停行为。Windows 实际前台进程观察确认本次全部采样在前台，不把后台允许选项当作后台性能证据。测试与其他游戏、编辑器、Blender 或截图录制错开。最小化、源资产变化、运行时错误、计时不可用或开关配对条件不一致会使相应记录失效；短时 pilot 只验证工具通路。方法、指标含义和输出文件详见 [P1 性能工具说明](../p1/README.md)。

GPU 计时仅覆盖根视口；工作集、私有提交、引擎内存和显存分别记录。动态开关保留常驻资源，内存波动不能解释为关闭风水可节省的资产占用。一次当前机器的结果也不能代表低/标准/高三档、其他设备、完整天气时段矩阵或移动玩法与故事舞台的性能。

## 构建与回归

仓库根目录的构建脚本会生成并核验离线内容、音轨和字体，运行状态、词故事、角色、果园、完整旅程及原有场景/交互检查，然后导出 Windows 并执行成品冒烟：

```powershell
.\build-game.ps1
```

若只复核本轮完整旅程，可在已完成资源导入的本机运行：

```powershell
& 'F:/Tools/Godot/4.7.2/Godot_v4.7.2-stable_win64_console.exe' --headless --fixed-fps 60 --path game --script res://tests/test_journey_game.gd -- --test-harness
```

这个命令只验证源码场景，不替代 Windows 导出或性能测试。本轮构建、最终 EXE/PCK、许可证与 ZIP 信息见上方“发布核验状态”；历史 `v0.5.0` 报告及离线包保留。
