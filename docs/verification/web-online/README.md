# v0.13.0-dev 网页邀请房间

> 本文保留首次网页联机实现的验证记录。后续已增加电脑单机与网页共享角色、网页单人模式、同步状态及冲突恢复；当前操作与存档位置以 [角色与进度互通](../shared-save/README.md) 为准。下文「服务不接收学习记录」「原单机存档不参与」描述的是该次历史实现，已由本机共享存档服务替代；房间广播仍只包含同行信息。

本轮按「打开网址就能加入；先按本机，后面再添加域名并部署服务器」实现。运行地点为 F:\LoveStudy，网页服务默认地址 http://127.0.0.1:4189/，仅本机可访问。

## 使用

1. 双击根目录「启动网页联机.cmd」。服务在后台启动，健康检查成功后打开浏览器；再次启动会复用当前服务。
2. 选择新角色或已有角色，填写昵称、选择衣服，点「创建小岛房间」。首次打开会下载约 624 MB 的场景包和引擎，随后进入现有 3D 字母岛。
3. 点顶部邀请码复制邀请链接。在另一个浏览器页面打开链接，选择另一个角色加入。最多 4 人；同一个角色不能在两个页面同时读写存档。
4. 用 WASD / 方向键或点地面行走；E 互动，M 地图。顶部「挥挥手」向同房间玩家打招呼。「朋友」查看所在场景，点「去找朋友」进入其场景并走向对方。进入室内时按需下载资源。
5. 顶部「离开房间」先走原有未完成绘画、学习事务与保存检查，再确认浏览器存档已写入。保存失败会留在游戏，允许稍后重试。退出后可继续在入口选择角色和房间。
6. 双击「停止网页联机.cmd」停止当前项目管理的服务。浏览器角色记录保留；房间是内存会话，重启服务后需要重新创建。

刷新页面会尝试用原身份重连；临时掉线有 90 秒保留期。进入失败、房间已满或邀请码无效会显示提示。浏览器页面长期关闭、清除网站数据、换浏览器或换端口会影响本地记录的可见性。当前没有账号、云存档和跨设备同步。

## 当前共享范围

同步玩家昵称、位置、朝向、移动状态、所在场景、服装和挥手。不同场景的玩家不会显示在当前画面中；原 NPC、物品、装饰、钱币、生活任务、学习与回访记录仍由各自管理。没有多人抢物品、交易、协作任务、语音或文字聊天。

网页角色使用独立 `/userfs/online-profiles/<profile-id>/progress.json` 和相同绝对路径的 IDBFS 挂载，原 Windows 正式存档不参与网页联机。服务不接收学习、背包、画作或家长观察记录。

## 构建与维护

```powershell
./build-web-online.ps1
./start-web-online.ps1 -NoBrowser
./stop-web-online.ps1
./.local/web-online-venv/Scripts/python.exe web/test_server.py -v
node web/test_persistence.mjs
```

Godot 4.7.2 导出 `Web Online`，使用 WebSocket、单线程 WebGL 2 兼容渲染器；Python aiohttp 提供静态文件与邀请房间。场景包经过资源 MD5 检查，分成初始包和 43 个室内包；每个室内包在引擎加载前检查 SHA-256。带内容哈希的文件可长期缓存，入口和脚本要求重新验证。`build/web-online/build-info.json` 记录本次产物大小与哈希。

当前模板的正常退出曾出现 PagedAllocator 错误；网页退出改为暂停游戏、等待 IDBFS 写入完成、返回入口，再次进入时重载引擎。`scripts/prepare_web_runtime.py` 在已检查的模板接口旁加入显式保存完成接口，将引擎和网页发起的并发同步合并为同一次事务；匹配点不是唯一时构建会失败，避免升级模板后悄悄绕过存档。下载室内包使用浏览器 fetch 写入引擎内存文件系统，再由 Godot 校验并装载。入口为样式、交互和引擎脚本加上内容哈希参数，防止旧浏览器缓存混入新构建。

## 后续部署

本轮没有配置域名、开放防火墙、路由器端口或部署公网服务。正式放到服务器时需要 HTTPS / WSS、持久化与版本发布策略、资源体积与并发压力评估。局域网 HTTP 地址不具备当前角色锁和浏览器存储所需的安全上下文条件，不能把本机链接直接发给另一台电脑当作已完成的远程联机。
