# 字母岛运行优化 · 2026-11-21

本次改动已接入当前源码运行入口：[启动字母岛](../../../启动字母岛.cmd)。新增的运行验证覆盖存档、经济、家校互动、语音、桌面与网页共享角色。17 组相关验证通过，验证前后 4 份现有存档文件的 SHA-256 均未变化。[完整结果](verification.json)

## 游玩时的变化

- **长期进度保留。** 首次奖励记录超过 2,000 条、任务完成记录超过 240 条后继续保留；当天奖励和仍生效的冷却记录不会因为列表变长而失效。损坏的等级字段会触发已有备份恢复，避免把异常数据当成初始进度覆盖。没有经验或叶币的完成记录也会保存，写入失败时一并回滚。
- **家具库存不再多扣钱。** 同款家具已有 99 件时拒绝继续购买，叶币和库存保持不变。
- **声音跟随当前操作。** 关闭对话、切换角色或房间、开启静音时，旧声音会停止；过期的朗读、聊天、跟读回复和录音不会进入新对话。开始跟读前先停下伙伴的朗读。
- **跟读反馈依据真实音频。** 按 WAV 的采样率、声道和实际数据计算音量、时长。麦克风不可用或录到静音时不再填入虚假的音量值；默读和未识别出词句的尝试仍可获得参与鼓励，但不会写入“答对词语”的证据。识别文本匹配与独立掌握分别记录。
- **语音服务保持响应。** 相同内容、语言和角色的并发请求共用一次合成；本地模型和语音识别在后台线程运行。音频完整写入后才进入缓存，提示音不会占用神经语音缓存。云端尝试共用 3.5 秒预算，重复失败后短暂退回本地；客户端为模型首次加载保留 20 秒可取消的等待时间。
- **启动与重启更准确。** 启动脚本检查伴学服务标识；重启前核对进程所属工程和模块，端口被其他应用占用时保留该应用。不同端口使用独立日志，前台启动也能从任意当前目录正确定位工程。

### 本机测量

- 带 2,105 条首次奖励记录的样本，连续 100 轮读取等级、经验和进度摘要：旧实现约 **675 ms**，修复后约 **2.2 ms**。旧实现还会丢弃超出 2,000 条的记录，修复后完整保留。这是等级查询的局部测量。
- 真实服务同时接到 3 个相同的离线发声请求，首次加载约 **7.4 秒**，返回一致的有效 WAV；期间 117 次健康检查均有响应，最慢约 **426 ms**。这次冷启动实测暴露并推动修复了原客户端的 5 秒超时。[测量数据](live-companion.json)
- 4 份现有存档文件在整组验证与补充检查前后均保持原始哈希。原始存档路径与哈希清单仅保存在本机 `.local/maintenance-20261121/final/`。

## 复查命令

在工程根目录执行：

```powershell
& .local\ai-companion-venv\Scripts\python.exe scripts\verify_runtime.py --native --real-speech
```

默认执行无窗口的状态与交互回归、Python 语音逻辑和共享角色测试。`--native` 增加实际渲染窗口与截图；`--real-speech` 使用本机 Piper/Vosk 模型和独立缓存检查发声与识别。日志、结果 JSON、存档前后哈希与截图写入 `.local/runtime-verification/<时间>/`，也可用 `--output` 指定目录。

脚本同时检查进程退出码与 Godot 日志中的脚本错误，避免将“进程退出为 0、内部脚本却报错”当成通过。单个用例超时只会结束本次创建的子进程树。

当前源码按原入口启动；Windows/Web 历史导出包的内容不属于本次验证范围。
