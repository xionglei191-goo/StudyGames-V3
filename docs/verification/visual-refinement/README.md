# 院子与客厅的实机画面对照

本目录验证 `home_estate` 院子和 `home` 客厅的美术精修。截图脚本是 `game/tests/capture_visual_refinement.gd`。

后续已修复客厅发现展示牌遮挡衣柜的问题，独立验证与最新客厅截图见 [展示牌避让记录](../home-display-layout/README.md)。对比页使用该次修正后的客厅图片；本目录的原始精修证据保留。

## 最终交付与本机运行结果

`after/` 是最终运行时资产和灯光配置下的 6 张 Godot 原生 1440×900 图，26/26 项检查通过。两个场景各含实际生产机位、全景审查机位和细节审查机位，全部与原始 `before` 的相机变换一致；已逐张目检。地板、草地与墙面的密集自阴影网点已修复，保留家具、角色与植物正常投影。院子使用单区正交阴影，客厅保持原级联模式，AO 强度均为 0.55。

`capture-after-errors.log` 为空；正式存档、备份及用户合照等文件哈希前后一致，生产源码与 GLB 在捕获期间不变。完整相机、源文件 SHA256 与用户文件签名在 `after/report.json`。`pre-shadow-fix/` 保留修复阴影前的中间资产截图，不作为最终交付。

最终性能在正常游戏处理运行、白昼晴天、减少动态、实际默认入场机位采样；没有禁用整个游戏节点，也没有传 `--fixed-fps`。每室在保存 PNG 后预热 60 个物理帧及 3 秒，再采样 300 个处理帧。

| 场景 | 实际墙钟 FPS | 帧间隔 p95 | 最后帧 Draw calls |
| --- | ---: | ---: | ---: |
| 院子 `home_estate` | 65.08 | 19.462 ms | 4,512 |
| 客厅 `home` | 100.01 | 10.448 ms | 841 |

设备为本机 RTX 4070，窗口 1440×900。本表是一次局部采样，不是最低配置承诺、全场景游玩结论或独占 GPU/CPU 耗时。Godot process/physics 监视值为粗粒度引擎指标，报告分别保存墙钟帧间隔和模拟 delta，不能混称为系统 CPU 耗时。此前阴影修复前的院子约 55 FPS 与最终约 65 FPS 属于不同运行轮次；受控因果对照见后文 `shadow-mode-probe/`。

## 灯光初次校准

`lighting-pass/` 保存增加主光、降低环境光后的第一轮结果，尚未包含后续模型与材质精修，也不是最终画面。原生 6 张截图通过 25 项检查，与基线的生产和审查镜头一致，错误日志为空；正式存档与合照签名未变。该轮画面存在直射偏亮、地毯偏艳的问题，已反馈用于后续调整。

该轮每室预热 60 个物理帧，采样 300 个处理帧，未启用 `--fixed-fps`。本机 RTX 4070 / 1440×900 / 晴天 / 默认机位的墙钟采样为：院子约 68.65 FPS、帧间隔 p95 17.65 ms；客厅约 99.99 FPS、p95 10.56 ms。它们不是最低配置承诺或完整游玩性能结论。Godot 的粗粒度 `TIME_PROCESS` 监视值仍残留此前保存 PNG 的慢帧，因此报告中的旧 `cpu_process_ms` 数值不能作为稳定 CPU 耗时；原始数值保留。后续脚本增加了 3 秒预热并将指标改名为 `engine_process_monitor_ms`，明确区别于操作系统 CPU 独占耗时。

此轮仅记录 SSAO 配置，是否生效由下方独立冻结对照判断。

## SSAO 原生冻结对照

`ssao-probe/`：17/17 项通过，`ssao-probe-errors.log` 为空。固定原始 `home-detail` 审查机位、晴天和低动态后，递归禁用游戏节点及子节点处理，冻结世界时钟和角色。依次捕获强度 1.15 两次、关闭 SSAO、强度 0.5，其余状态不变。

同条件强度 1.15 的两图 SHA256 与逐像素结果完全相同。1.15 与关闭对比有 196,391 个像素改变（15.1536%，最大 RGB 通道差 18/255）；1.15 与 0.5 有 190,937 个像素改变（14.7328%，最大差 10/255）。本机 Godot 4.7.2 Compatibility 下 SSAO 已通过可见输出验证，不能描述为“属性存在但完全无效”。原始图片、冻结状态与 `pixel-analysis.json` 均保留。

关闭 SSAO 后地板与墙面仍有细密点纹，说明不能仅凭该现象将问题归因于 SSAO。`ssao-probe-unfrozen/` 是首次探针失败的原始记录：LivingWorld 的 `PROCESS_MODE_ALWAYS` 绕过了只禁用父节点的设置；它的时钟守卫失败，因此不用于严格像素对比。正式探针已递归禁用所有节点并通过重复图一致性检查。

`shadow-probe/`：14/14 项通过，错误日志为空。保持 SSAO 关闭和所有节点冻结，比较原始阴影 bias（0.025 / normal 0.55）、关闭阴影、bias 0.1 / normal 1.0 三种状态。较大的 bias 明显消除了地板与墙面密集网点，并保留家具和角色正常投影；关闭全部阴影虽也消除网点，但画面整体异常变暗，不作为修复方案。该结果将主要问题定位在原阴影 bias，而不是 AO 配置本身。三张原生图和参数、相机、时钟及源签名记录均保留。

## 镜头和证据边界

`-production` 使用实际游戏的默认入场位置、跟随镜头和 HUD。脚本等待实际生产镜头更新，不覆盖镜头参数。

`-overview` 和 `-detail` 是明确标注的美术审查镜头，暂时隐藏 HUD。精修后读取基线报告中的完整相机变换，确保同机位对照；生产镜头的变换也逐项比较，发生变化时报告失败，而非强行覆盖为旧镜头。

本截图阶段直接进入两间场景，以快速建立美术基线；它不证明玩家能够从院门走到屋内，也不替代门口通行、房内移动或碰撞检查。实际通行检查由 `gameplay-report.json` 单独报告。

交付画廊由原生截图组成，`gallery-check.json` 记录 6 组 / 12 张图的存在性、尺寸、相机容差检查和当前 7 份生产文件 SHA 检查均通过；浏览器对 `file://` 的安全策略拒绝了交互访问，因此不宣称画廊已通过浏览器交互验收。图像本身均通过原生截图和逐张查看核验。

所有截图固定白昼、晴天、减少动态，并静音主音频总线、语音及音效。脚本要求 `--test-harness`，由游戏创建本进程专用 `user://validation-<PID>.json`；结束后只清除本进程的验证存档及其备份/临时文件。

## 重现命令

必须使用原生图形运行，不要给截图命令加 `--headless`。每次仅运行一个截图进程。

```powershell
& 'F:/Tools/Godot/4.7.2/Godot_v4.7.2-stable_win64.exe' --path 'F:/LoveStudy/game' --fixed-fps 60 --script res://tests/capture_visual_refinement.gd -- --test-harness --refinement-stage=after
```

需要同时采样实际墙钟性能时去掉 `--fixed-fps 60`，增加 `--refinement-performance`。定向通行验证命令为：

```powershell
& 'F:/Tools/Godot/4.7.2/Godot_v4.7.2-stable_win64.exe' --headless --path 'F:/LoveStudy/game' --fixed-fps 60 --script res://tests/test_visual_refinement.gd -- --test-harness
```

隔离探针分别使用 `res://tests/probe_refinement_ssao.gd`、`res://tests/probe_refinement_shadow.gd`、`res://tests/probe_refinement_shadow_mode.gd`；均需原生渲染及 `-- --test-harness`。最后一项包含性能测量，不应传 `--fixed-fps`。探针仅修改内存中的环境和光照，不写生产源码或源材质。

`before` 已在精修改动前保存，不应在修改后的工程上重新覆盖。`after` 要求存在 `before/report.json`。

启动时检查 Godot/Blender 进程及显存占用。本次基线启动前无 Godot/Blender 进程，GPU 显存约使用 2.8 / 12.3 GB；截图进程完成后已退出。
