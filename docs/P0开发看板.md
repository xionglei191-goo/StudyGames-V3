## 一、P0 目标

做出一个真正像 RPG 的首个可试玩闭环：

- 第一眼看到星光小镇地图，而不是任务卡片或书房场景。
- 玩家角色可以在地图上移动。
- 钟塔、Keeper Ray / 公告牌、邮局入口可以交互。
- 主画面持续提示当前目标和下一步地点。
- 从地图接取第一个委托，进入邮局书房完成挑战。
- 完成后回到小镇，看到第一个星片或钟塔修复变化。

> 范围：只定义 RPG 主体验 P0 的最小技术边界，不改写现有学习挑战、奖励、进度系统。

负责范围：

- Phaser 小镇地图、角色移动、地图交互。
- React 顶部状态、HUD、冒险日志的职责边界。
- EventBus 与 `TaskRuntime` 的连接方式。

交付要求：

- 明确默认入口必须是 `scene_town`。
- 明确点击移动或方向键移动的首版方案。
- 明确地图交互如何触发任务开始、场景跳转和完成后回流。
- 明确保留现有 `TaskRuntime` 和奖励结算，不重写任务判定。

阶段性交付：

- [x] 默认入口：Phaser 资源加载完成后进入 `scene_town` / `TownScene`。React 初始 `sceneId` 保持 `scene_town`，不把任一学习挑战场景作为首屏。
- [x] 移动方案：首版点击移动优先。玩家点击地面或交互点时，Phaser 只负责角色朝目标点移动、落点反馈、靠近提示；方向键可作为桌面补充，但不能成为手机端必需操作。
- [x] 地图布局：首屏固定为小镇小地图，不做开放世界。建议首版落点为：玩家出生点在镇口道路，钟塔在左上或中左主视觉，Keeper Ray / 公告牌在出生点到钟塔之间，邮局入口在右侧或右下，花园和镇口作为可见但非首轮必触发地点。
- [x] Phaser 边界：负责 `TownScene` 绘制、玩家角色、点击移动、三处地图交互点、靠近范围、地图状态刷新和完成后的可见修复效果；不直接判定学习步骤是否完成，不直接发放奖励。
- [x] React 边界：负责顶部成长状态、短 HUD、奖励预览、冒险日志详情、结算弹层和面板降级；右侧日志只能补充背景，不能替代地图上的目标标记和交互反馈。
- [x] EventBus 边界：作为 Phaser 与 React 的轻量消息通道。推荐事件语义为：`town:interaction` 传递交互点，`town:move-target` 传递目标点，`ui:focus-task` 请求 React 启动指定委托，现有 `task:started` / `task:progress` / `task:completed` 继续由 `TaskRuntime` 发出。
- [x] `TaskRuntime` 边界：只在玩家从地图明确触发邮局入口或委托开始后调用 `taskRuntime.start(taskId)`；学习步骤、反馈、完成、奖励、经验、星片、进度保存继续走现有 `TaskRuntime`、`progressStore` 和奖励结算。
- [x] 任务触发：Keeper Ray / 公告牌只负责“接到委托”和更新 HUD 下一站，不直接进入挑战；邮局入口在玩家靠近或点击确认后，通过 `ui:focus-task` 启动 `task_eng_g3b_u01_main`，React 调用现有 `startTask()` 并 `navigateToScene(task.sceneId)`。
- [x] 完成回流：`task:completed` 后 React 保留现有结算和奖励弹层；玩家关闭或点击继续时回到 `scene_town`。`TownScene` 读取 `progress.completedTaskIds` / `starShard.collectedIds` 推导钟塔第一格微亮、问候星片点亮或镇口欢迎光变化。
- [x] 最小地图状态：优先从现有进度推导，例如 `task_eng_g3b_u01_main` 是否完成决定第一处地图变化；如需临时 UI 状态，只允许增加本地前端状态如 `currentTownObjective`、`lastInteractionId`、`returnFromTaskId`，不引入后端、全局状态库或新大型框架。
- [x] 旧 UI 降级：任务卡、冒险日志、地图面板保留为辅助信息；首屏不得用大卡片覆盖小镇地图，不能把“开始”按钮作为唯一入口。

风险说明：

- [ ] 当前代码中如存在进入小镇即自动启动当前任务的路径，需要代码组改为“地图交互后启动”，否则会削弱从地图接委托的体验。
- [ ] 点击移动如果没有靠近阈值和落点反馈，孩子会以为点击无效；代码组需给目标点光圈、角色移动和到达提示。
- [ ] 从任务完成回小镇时，如果只显示结算弹层而地图不变，奖励用途仍不清楚；代码组和 UI 组必须联动展示钟塔或星片变化。
- [ ] 手机端只接受点击移动作为稳定路径；方向键、键盘快捷方式不能写进 P0 必需流程。
- [ ] 本方案不新增战斗、背包、后端、AI 动态内容，不扩展到 75 个任务。

#### 1. 平面小镇地图布局规格

P0 首屏必须呈现“可玩的俯视 / 斜俯视小镇平面图”，不是整张故事插画加点击热区。

- 地图形态：使用平面小镇地图构图，玩家能看出道路、建筑、场地和可走区域的关系；允许手绘风格，但必须像游戏地图，不像单张封面插画。
- 主路结构：从底部或左下“镇口”进入，主路延伸到中央广场，再分成 3 条短支路：钟塔方向、邮局方向、花园 / 天气台方向。
- 钟塔：位于中央偏上或左上，是首屏视觉锚点；底部必须贴在广场或石板地面上，周围留出玩家可站立区域。
- 公告牌 / Keeper Ray：位于镇口到钟塔之间的主路旁，属于低矮交互物或 NPC 点位，不能悬浮在画面中央。
- 邮局：位于右侧或右下支路尽头，入口门朝向道路；门前保留一块清晰落脚区，用作进入学习挑战的触发点。
- 钟塔铃台：作为钟塔右侧或钟塔脚下的附属小平台，有铃铛、时间标记或小闹钟提示，服务第 2 个委托。
- 天气台：位于花园入口或右下开阔处，有天气牌、风向标、云朵 / 太阳符号，服务第 3 个委托。
- 镇口：位于玩家出生点附近，有欢迎光、路牌或拱门提示“从这里进入小镇”，但不能做成大面板。
- 花园 / 河流：花园作为右下或下方绿地区域；河流可沿边缘穿过或在花园旁形成浅蓝边界，用于丰富地图层次，但不能切断 P0 主路。
- 可走区：道路、广场、建筑入口前的落脚区必须视觉连续；建筑、花坛、河流边界应清楚暗示不可走或非主路径。
- 交互点落位：钟塔、公告牌 / Keeper Ray、邮局入口、铃台、天气台必须贴地，有光圈、地面标记或小箭头与物体底部对齐。
- 禁止做法：不得用一张大背景插画表现小镇，再把交互区域藏在透明热区里；不得让道路、建筑和角色没有空间比例关系。

#### 2. 微缩角色视觉规格

玩家角色必须是地图上的微缩可移动角色，而不是大立绘、固定人物图片或卡片头像在背景上平移。

- 尺寸：桌面视口中角色高度建议为地图主视觉高度的 5%-8%，约等于邮局门高的 1/2 到 2/3；手机视口中可略放大到 7%-10%，但不得压过建筑入口。
- 比例：采用 Q 版 / 儿童冒险微缩比例，头身约 1:2 到 1:3；头、身体、脚底位置稳定，不拉伸、不横向变形。
- 锚点：角色脚底为移动锚点，落在道路或广场上；所有移动、转向、点击到达判断以脚底坐标为准。
- 移动动画：移动时必须有步行动画感，至少包含左右脚交替、身体轻微起伏或 2-4 帧循环；不能只是整张静态图片匀速滑动。
- 朝向：至少支持左右朝向；如工作量允许，补前 / 后朝向。角色朝移动目标转身，停下后保持最后朝向或面向交互点。
- 影子：角色脚下有小椭圆软影，随角色移动；影子贴地，不跟身体分离，用来强化微缩角色站在地图上的感觉。
- 停靠反馈：到达交互点时角色应停在物体前的落脚区，不站进建筑、光圈或河流里。
- 禁止做法：不得使用大立绘头像作为可移动玩家；不得让固定图片在插画背景上滑动来伪装角色动画。

#### 3. HUD 和地图标签降噪规则

首屏要先读出“小镇地图 + 可移动角色 + 目标点”，HUD 只能做轻量指路。

- HUD 层级：顶部或角落只保留当前目标、下一步地点、奖励预览三类短信息；每项一行短句，不堆长段剧情。
- 地图标签：地点名只在交互物附近以小标签或气泡出现；默认显示不超过 3 个重点标签，其他标签靠近或点击后再出现。
- 气泡规则：NPC / 地点气泡必须贴近对应对象，宽度受限，文字 1-2 行；长说明进入冒险日志，不压在地图中心。
- 面板规则：不得在首屏叠多个大白框、大卡片或右侧说明墙；日志和详情可以收起或放到辅助区，不能抢走主地图第一视觉。
- 遮挡规则：HUD、标签、气泡不得盖住钟塔主体、邮局入口、玩家角色、当前目标光圈和主要道路分叉。
- 手机规则：手机端 HUD 优先使用顶部短条或底部半透明短栏；不得把地图压缩到只剩背景，也不得让白框覆盖主要可走区。
- 视觉噪音：同一时刻只强调当前下一步目标；已完成星片可以保留轻量进度标记，但不能每个建筑都常驻大标签。

8. 回到小镇，看到钟塔或星片状态变化。

## 五、R3 三任务地图化验收流程

R3 验收不是只确认 3 个任务仍可完成，而是确认玩家每次都从星光小镇继续下一段主线。

1. 从新存档或清空进度状态进入游戏，第一屏是星光小镇地图。
2. 按首轮流程完成 `小镇门口见面礼`，回到小镇后看到问候星片点亮第 1 格。
3. 主画面 HUD 更新为 `去钟塔铃台找 Mina`，地图上钟塔铃台 / Mina 标记可见。
4. 玩家移动到钟塔铃台，触发 Mina 或铃台气泡，接到 `帮 Mina 赶上铃声`。
5. 从钟塔铃台进入现有任务运行时，完成后回到小镇。
6. 小镇显示小闹钟装饰点亮第 2 格，铃台出现可见恢复变化，HUD 更新为 `去天气台看看天空`。
7. 玩家移动到天气台 / 花园入口，触发天气台气泡，接到 `天气出门准备`。
8. 从天气台 / 花园入口进入现有任务运行时，完成后回到小镇。
9. 小镇显示天气贴纸点亮第 3 格，钟塔第一圈星路完整点亮。
10. 完成 3 个星片后，HUD 显示 `第一圈星路已点亮`，下一步地点指向钟塔星路或校园星门线索。

R3 验收 checklist：

- [x] 第 2 个委托必须从小镇钟塔铃台 / Mina 触发，不能只从侧边任务列表启动。
- [x] 第 3 个委托必须从小镇天气台 / 花园入口触发，不能只从侧边任务列表启动。
- [x] 第 1、2、3 个星片分别有地图可见进度：问候星片、小闹钟装饰、天气贴纸。
- [x] 完成第 3 个委托回镇后，钟塔第一圈星路在地图上完整点亮。
- [x] `TaskRuntime`、奖励结算、XP、等级、星片、回访不重复发奖逻辑不回退。
- [x] 桌面和手机截图均无地图遮挡、文字出框、按钮漂浮、角色变形、点击偏移。
